# 为什么要手写一个个人网站

现成的博客框架、模板主题一抓一大把，为什么还要自己写一个？

因为我发现，用别人的框架时，我大部分时间花在**和框架的约定较劲**上：主题怎么改、插件怎么配、构建怎么调。而我真正想做的事只有一件——把想法写下来，让别人能读到。

## 我想解决的问题

- **写作路径要短** — 打开编辑器写 Markdown，保存，刷新，结束。不要构建，不要部署脚本
- **结构要能看懂** — 一个 HTML、一个 CSS、一个 JS，任何时候打开都能读懂
- **换台电脑也能跑** — 不需要装 Node，不需要联网下载依赖

## 技术选择

| 需求 | 选择 | 原因 |
| --- | --- | --- |
| 内容格式 | Markdown | 纯文本，十年后还能读 |
| 渲染 | marked | 一个 CDN 文件搞定 |
| 路由 | hash | 静态托管零配置，子路径也不会 404 |
| 样式 | 原生 CSS 变量 | 明暗主题切换只需要改一个属性 |

> 工具应该是透明的：用得越久，你越感觉不到它的存在。

## 三条自我约束

1. **不引入构建步骤** — 只要刷新浏览器就能看到结果
2. **不依赖后端** — 纯静态，扔到任何托管上都能跑
3. **代码必须能读懂** — 半年后的我打开 `app.js`，要能十分钟内定位到修改点

## 下一步

先把内容补起来，再考虑加归档页和 RSS。功能不着急，**能持续写下去才是这个站点存在的意义**。
