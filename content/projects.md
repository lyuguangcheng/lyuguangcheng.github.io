# 项目

我做东西的习惯是：先想清楚它替谁解决了什么问题，再决定用什么技术。下面每个项目都尽量写清楚「为什么做」和「做到了什么」，而不只是罗列技术名词。

## 怎么挑项目

- **有具体的使用者** — 哪怕只有我自己用，场景也要足够明确
- **能一个人做完** — 从设计到上线全流程走一遍，学得最快
- **能留下点什么** — 要么是可复用的代码，要么是一篇复盘

## 关于技术选型

我倾向于**先用最朴素的方式实现一遍**。很多时候，几百行原生代码比引入一整套框架更好维护，也更容易看懂。等需求真的复杂到需要框架时再引入也不迟——那时你已经清楚它到底帮你解决了什么。

```js
// 简单优先：能写清楚，就不要写聪明
const render = (items) => items.map(toCard).join('');
```
